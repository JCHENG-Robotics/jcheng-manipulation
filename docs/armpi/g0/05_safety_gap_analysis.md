# 05 · 安全差距分析（SR-01…SR-10）

> 证据等级：`Verified in source` / `Unknown`（实机行为）
> 对应 PRD：§6 安全需求、§11 测试门禁
> 结论先行：**当前厂商栈不具备 Web 端安全运动所需的闭环证据；G1 只能以“默认拒绝 + 只读优先 + 人工看护”启动。**

---

## 1. SR 逐条差距

| 编号 | PRD 要求 | 当前事实 | 差距 | G1 应对 |
|---|---|---|---|---|
| SR-01 | 默认拒绝运动：未完成检查/映射/限位/控制权，不发运动 | 厂商 `servo_controller` 收到 `/servo_controller` 就下发；无门禁 | **不满足** | 后端 `SafetySupervisor` 默认拒绝；UI 默认只读 |
| SR-02 | 服务器侧再次校验 | 厂商层只做静默裁剪，不校验、不拒绝 | **不满足** | 所有校验在后端完成；厂商裁剪视为最后一道但不可依赖 |
| SR-03 | SDK 阻塞读取须由隔离/有界调用包裹 | `queue.get(block=True)` 无超时；单线程 executor 会被冻结 | **不满足** | 客户端超时 + 熔断；禁止高频轮询；推动 Driver 修补（需批准） |
| SR-04 | 故障锁存，人工确认后恢复 | 无故障状态、无锁存、无恢复流程 | **不满足** | 后端故障锁存 + 重新体检 + 显式 re-arm |
| SR-05 | 限位实机测量；规划碰撞不替代物理防护 | 只有 `servo_controller.yaml` 软件范围；URDF 与软件冲突 | **不满足** | 标记 `provisional`；未验证前只允许受限测试 |
| SR-06 | 区分“停止请求/控制器确认/实际停止/断电” | `bus_servo_stop` 无 ACK；无位置校验 | **不满足** | 停止状态机四态；无法验证时显示 `Unknown` |
| SR-07 | 默认 localhost/可信局域网；远程需认证/TLS | 现有 `bringup` 启动 rosbridge + web_video_server，无认证 | **不满足** | 后端默认绑定 `127.0.0.1`；不暴露 rosbridge 给浏览器 |
| SR-08 | Simulation/Replay 与 Live 用不同适配器；Replay 无写权限 | 不存在这些模式 | **不满足** | 适配器隔离；Replay 适配器写方法直接抛错 |
| SR-09 | 无人值守执行需独立评审 | 厂商 `startup_check` 会在启动后自动发 home 姿态 | **高风险** | G1 禁止使用完整 `bringup.launch.py`；不实现无人值守 |
| SR-10 | 单一串口所有者 | 至少 4 条路径可打开 `/dev/rrc` | **不满足** | 启动前探测；UI 显示“串口可能被占用” |

## 2. 启动即写硬件的既有行为（必须知道）

| 位置 | 行为 | 影响 |
|---|---|---|
| `ros_robot_controller_node.py:69` | `pwm_servo_set_offset(1, 0)` | 每次启动写 PWM 偏移（ArmPi Ultra 用总线舵机，可能无实际效果，但仍是硬件写） |

| `sdk/sdk/hw_interfaces.py` | 构造时 `buzzer_off()` / `led_off()` | 非运动，但仍是硬件写 |

> G1 的启动方式应只包含 `ros_robot_controller` + `servo_controller`（不含 `grasp`、`startup_check`、底盘），并记录启动时的硬件写副作用。

## 3. 故障场景矩阵

| 场景 | 命令是否被拒绝 | 机械臂实际响应 | 现有证据来源 | 结论 |
|---|---|---|---|---|
| 网络断开 | 断开后新命令无法到达 | **继续执行最后一条已下发的“时长+目标”命令**，然后停在目标 | 无 | `Unknown`；必须由后端租约+看门狗降低风险 |
| 浏览器关闭 | 无新命令 | 同上 | 无 | 同上 |
| 后端崩溃 | 无新命令 | 同上 | 无 | 同上 |
| Driver 退出 | 新命令无消费者 | 舵机执行完最后命令后保持 | 无 | `Unknown` |
| 反馈超时 | 本系统可拒绝新命令 | 与反馈无关（开环） | 无真实反馈 | 必须显示 `Unknown`，不能显示“正常” |
| 串口断开 | 后端可拒绝 | 舵机可能保持最后目标或失力 | 无 | `Unknown`；需实机验证 |
| 非法目标（超限） | 当前厂商层 **静默裁剪** | 移动到裁剪后的位置 | 源码 | 后端必须前置拒绝 |
| 重复点击 | 当前无幂等 | 重复下发相同目标 | 源码 | 后端 `Idempotency-Key` + 单飞 |
| 两个控制源同时发 | 当前无仲裁 | 后发者覆盖，可能来回抖动 | 源码 | 后端租约；但仍需 ROS 侧唯一写者 |
| 未知关节 ID | 厂商层 **静默丢弃** | 无动作、无错误 | `servo_controller.py:73-79` | 后端必须拒绝并记录 |
| 重连后自动运动 | 当前无自动重连 | 若用完整 bringup，`startup_check` 会发 home | 源码 | G1 禁止该 launch；重连不自动恢复 |
| 急停后重新使能 | 无急停信号 | `Unknown` | 无 | 显示 `Unknown`；要求物理断电确认 |

> “机械臂实际响应”一列，除源码可证明的静态行为外，**全部是 `Unknown`**。G1 的 UI 不得把这些填成确定值。

## 4. 命令状态机与证据规则

PRD 要求的状态：`Requested / Validated / Dispatched / Acknowledged / Observed / Completed / Failed / Unknown`。

在本厂商栈上：

| 状态 | 可用的证据 | 是否可实现 |
|---|---|---|
| `Requested` | 后端收到请求 | ✅ |
| `Validated` | 后端校验通过 | ✅ |
| `Dispatched` | ROS publish 返回（仅表示进入 DDS） | ✅ |
| `Acknowledged` | **没有 ACK 机制** | ❌ 不得使用 |
| `Observed` | 独立 `GetBusServoState` 读回位置 | ⚠️ 依赖 D-10；有超时/错配风险 |
| `Completed` | `Observed` 在容差内且持续 N 次 | ⚠️ 仅在 D-10 通过后启用 |
| `Failed` | 校验失败 / ROS 调用异常 | ✅ |
| `Unknown` | 超时、无证据、读回不可信 | ✅ 必须是一等状态 |

**规则**：

1. 不允许 `Dispatched → Completed` 的跳跃。
2. 没有独立读回时，命令最终状态必须是 `Unknown`，并写明“无反馈证据”。
3. `Acknowledged` 在数据契约中保留字段，但本栈永远不产生。

## 5. 停止语义（SR-06）

UI 只能使用以下词汇：

| 状态 | 含义 | 允许的 UI 文案 |
|---|---|---|
| `StopRequested` | 后端接受停止请求 | “已提交停止请求” |
| `StopDispatched` | 已向 ROS 发布停止命令 | “停止命令已下发” |
| `StopObserved` | 读回位置在短时间内不再变化 | “观察到位置停止变化” |
| `StopUnknown` | 无法验证 | “停止结果未知” |

**禁止**：

- “急停 / Emergency Stop / E-Stop”
- “已停止”而没有读回证据
- 用红色大按钮暗示硬件安全功能

推荐文案：**“停止请求（软件）—— 非急停，物理断电仍是最终防护”**。

## 6. G1 运动门禁（Proposed）

后端在每次运动前逐项检查，任一失败即拒绝并返回结构化原因：

| # | 检查 | 数据来源 | 失败状态 |
|---|---|---|---|
| 1 | 模式为 `hardware` 且 `hardware_motion_enabled=true` | 配置 | `Rejected` |
| 2 | 适配器健康、Driver 节点在线 | ROS graph | `Disconnected/Degraded` |
| 3 | `/dev/rrc` 存在（只读探测） | 文件系统 | `Fault` |
| 4 | `GetBusServoState` 对 6 个舵机在超时内返回 | 服务探测 | `Fault` |
| 5 | 映射 `verified=true`（或处于受限测试模式） | `joint_mapping.yaml` | `Rejected` |
| 6 | 限位 `hardware_verified=true` | `joint_mapping.yaml` | `Rejected`（受限模式除外） |
| 7 | 当前会话持有控制租约且心跳新鲜 | 租约存储 | `Rejected` |
| 8 | 无锁存故障 | 故障存储 | `Fault` |
| 9 | 反馈年龄 < 阈值 | 最近读回时间 | `Unknown/Rejected` |
| 10 | 操作者已勾选“现场看护 + 可断电” | 会话 | `Rejected` |
| 11 | 单串口所有者已确认 | 启动探测 | `Warning`（可配置为阻断） |
| 12 | 目标通过全部数值校验 | 请求 + 映射 | `Rejected` |

> 第 5/6 项在 G1 初期必然为 false。因此 G1 的“运动”只允许 **受限测试模式**：单关节、小步长、长时长、人工逐次确认。具体门槛需 Board 书面批准。

## 7. 前端红线（不可违反）

1. **不得**把 UI 停止按钮称为急停。
2. **不得**把 `joint_states` 标为“实际反馈/编码器”。
3. **不得**在 `Unknown` 时显示绿色/正常。
4. **不得**在 Hardware Mode 未实现时伪造连接成功或运动成功。
5. **不得**让滑块拖动直接触发运动；必须“预览 → 确认”。
6. **不得**在断线后自动重连并恢复运动许可。
7. **不得**隐藏 `Simulation/Replay` 标识。
8. **不得**用颜色作为唯一状态表达；必须同时有文字/图标。
9. **不得**展示没有数据来源的温度/电压/误差；无数据显示 `Unavailable`。
10. **不得**把“轨迹 Action succeeded”展示为“到达目标”。

## 8. 残余风险（G1 无法消除）

| 风险 | 原因 | 缓解 |
|---|---|---|
| 后端崩溃后机械臂继续执行最后命令 | 舵机自带“时长+目标”运动，无持续流 | 限制单条命令时长；人工看护；物理断电 |
| 停止命令无确认 | SDK 无 ACK | 停止后读回位置；无法验证则显示 `Unknown` |
| 反馈可能是回显 | D-10 未验证 | 在验证前不使用反馈做安全判断 |
| Driver 被一次读取冻结 | 无超时 | 限制探测频率；客户端超时；推动修补 |
| 串口被厂商工具占用 | 多所有者 | 启动探测 + 文档 + 进程检查 |
| 急停能力未知 | 无硬件信号 | 要求现场物理断电；显示 `Unknown` |

---

## 9. 安全结论

- 现有栈 **不满足** G1 的任何一条运动安全要求；它只能作为“被包装的开环执行器”。
- Debug Studio 的价值不是“让机械臂动”，而是 **在证据不足时明确说不知道**，并阻止在没有证据时运动。
- G1 的验收应包含：所有拒绝路径可复现、所有 `Unknown` 可解释、所有命令有审计记录。
