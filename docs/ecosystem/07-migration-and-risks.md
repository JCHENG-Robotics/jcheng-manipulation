# 迁移风险与实施顺序

> 原则：**基线不动、契约先行、Mock 先行、双轨运行、证据驱动、随时可回滚。**

## 1. 迁移原则

1. **不修改 `jcheng-manipulation v1.0.0`。** 不迁代码、不改标签、不改清单、不改证据。
2. **不做大爆炸切换。** 新系统与旧网关并行；旧路径保持可用直到新路径验收。
3. **契约先于实现。** `jcheng-interfaces` 未发布前，系统仓库不写跨仓库契约。
4. **Mock 先于实机。** L0–L4 全绿才允许 L5。
5. **单一权威。** 迁移期也只允许一个安全/租约权威；旧后端只能降级为客户端。
6. **证据化。** 每个阶段有出口证据；没有证据视为未完成。
7. **可回滚。** 每个阶段都有明确的停止与回滚步骤。
8. **最小权限。** 新模块从第一天就没有硬件访问；不靠“先跑通再收紧”。

## 2. 阶段计划

### M0 设计评审（当前）

**交付：**

- 本文件集（9 份文档 + ADR）。
- 评审意见与决策记录。

**出口条件：**

- 用户批准 `00-executive-summary.md` 第 6 节的五项决策。
- 明确首批仓库的可见性、许可证、组织名。

**不做：** 不创建仓库、不写代码、不接触实机。

**回滚：** 删除 `design/ecosystem-v1` 分支即可，基线不受影响。

- 没有产品代码、没有实机连接。

**回滚：** 删除三个仓库；组织设置可保留。

### M2 `jcheng-interfaces` v0.1.0

**出口条件：**

- 与 `v1.0.0` 的 `ValidateTrajectory` 语义映射文档完成。
- 没有节点、没有硬件依赖。

**回滚：** 不发标签；删除包内容；系统仓库尚未依赖。

### M3 `jcheng-system` 纯 Mock 骨架

**交付：**

- `jcheng_safety`（移植 `policy.py` 检查 + 状态机 + 锁存）。
- `jcheng_authority`（租约、TTL、优先级、撤销）。
- `jcheng_motion`（action 前端 + Mock 执行器）。
- `jcheng_hardware`（Mock 厂商桥，域 43）。
- `jcheng_gateway`（HTTP/WS/OpenAPI 子集）。
- `jcheng_guard`（发布者白名单）。
- `jcheng_testkit`（场景 S1–S17 的 Mock 版本）。
- 锁文件 schema 与 `verify_lock.py`。

**出口条件：**

- L0–L3 全绿；S1–S12、S15、S16 通过。
- 零非仲裁器硬件发布者。
- 契约不匹配、无租约、越限、停止锁存全部有测试。
- **不连接实机。** 域 0/41/42 不存在于本阶段运行中。

**回滚：** 停止 Mock 容器；无机器人影响。

---

### M4 机器人只读接入

**交付：**

- 机器人端特权容器（无串口设备）与 `jcheng_hardware` 只读模式。
- 域 0/41/42 配置；CycloneDDS 单播 peer。
- `jcheng_telemetry`：实测总线读数、`truth` 标注、证据记录。
- 只读网关/API：状态、安全、电池、相机、TF。
- 时钟/链路预检与健康检查。

**出口条件：**

- 只读运行 ≥ 30 min，无写入。
- 实测总线读数与旧网关一致（同一时刻比较，容差按脉冲）。
- 域隔离验证：能力域进程看不到厂商命令话题。
- **没有发送任何运动命令。**

**回滚：** 停止新容器；旧网关继续只读；无运动影响。

---

### M5 单关节/夹爪受监督执行

**交付：**

- `jcheng_motion` 执行器：step/pose/gripper profile。
- 安全节点完整校验 + 停止锁存 + 使能状态机。
- 安全节点心跳：缺失/过期即 `STOP_LATCHED`（关闭 fail-open）。
- 停止中止在飞轨迹/底盘脉冲；底盘归零、机械臂保持。
- 租约争用/抢占/过期；guard 运行时检测。
- 8765/8766 旧网关仅保留只读；新系统使用独立端口。
- S6、S7、S9、S10、S11 的硬件版本。

**出口条件：**

- 单关节 0.05 rad、夹爪开合各一次，全部总线确认。
- 软件停止传播 ≤100 ms（实测），且在飞命令在停止后不再产生新设定点。
- 停止安全节点进程后，新命令被拒绝（不得 fail-open）。
- 无租约/越权/越限命令 100% 拒绝。
- 旧路径仍可作为回滚。
- 证据包完整。

**回滚：**

1. 软件停止 + 解除使能。
2. 停止新系统服务。
3. 恢复旧 8766 网关（如已停用）。
4. 总线复核实际位置。
5. 记录回滚证据。

**停止条件：** 非预期运动、总线不一致、锁存无法清除、操作员要求停止。

---

### M6 基线回放与 G8 复验

**交付：**

- S13 回放：v1.0.0 录制轨迹 -> 新校验器 -> 决策对比。
- S14 底盘脉冲 + 标定失效。
- G8 全流程通过新系统执行（定位 -> 抓取 -> 抬升 -> 放回）。
- MoveIt 只规划验证（S17）。
- 性能指标：校验延迟、执行延迟、停止延迟。

**出口条件：**

- 回放决策一致率 100%（允许时间戳差异）。
- G8 落点在约定门槛内；无 `UNKNOWN`。
- 每阶段总线确认；证据包可校验。
- 旧网关仍未删除，可回滚。

**回滚：** 同 M5；额外恢复旧 G8 运行器（只读基线代码，不修改）。

### M7 首个外部模块试点

**候选：**

- `jcheng-applications`：只读 + 任务编排，最容易证明无硬件权限。
- `jcheng-teleop`：高频意图、deadman、抢占，验证实时性。

**交付：**

- 模块仓库、`capability.yaml`、契约握手、CI。
- 系统侧能力注册与白名单。
- 模块在域 42 运行；图形审计零硬件发布者。
- 受监督场景：租约申请 -> 意图 -> 执行 -> 停止。

**出口条件：**

- 模块无硬件访问（静态 + 运行时）。
- 租约/抢占/停止行为符合契约。
- 首次接入有 L5 证据。

**回滚：** 停用模块；系统回到 M6 状态。

### M8 生态 v1.0 发布

**交付：**

- 锁文件、SBOM、校验和、签名标签。

**出口条件：**

- G1–G12 指标达标（见 `06`）。
- 回滚演练成功。
- 无未解决的高风险项。
- 用户批准发布。

**回滚：** 恢复上一锁文件与镜像；旧网关只读；保留证据。

### 4.1 最高优先级风险

**R15（双权威）**、**R4（绕过）**、**R25（fail-open）**、**R27（停止不中止）**、
**R28（缓存当实测）** 是本次迁移的核心。任何阶段发现以下情况，
立即停止实机并回到上一阶段：

- 旧后端仍能独立判定租约/安全并直接命令网关。
- 新模块出现在域 0/41 或硬件命令话题。
- 两个进程同时持有同一执行器租约并都发出命令。
- 安全锁存后仍有运动命令被接受。

## 5. 双轨运行与切换

### 5.1 运行态

```text
阶段 M4：旧网关（只读） + 新系统（只读）
阶段 M5：旧网关（只读） + 新系统（运动，独立端口）
阶段 M6：旧网关（只读，回滚用） + 新系统（G8）
阶段 M7：旧网关（只读） + 新系统 + 首个模块
阶段 M8：旧网关（只读诊断，可选） + 新系统（唯一运动权威）
```

### 5.2 切换规则

- 运动权威同一时刻只有一个：M5 起新系统；旧网关的 motion 实例必须停止。
- 旧 8766 单元默认禁用；切换时显式停止并确认无 publisher。
- 回滚时先停新系统，再恢复旧网关；不得两者同时发布。
- 每次切换记录：时间、操作员、发布者集合、安全状态、证据 ID。

## 6. 回滚手册（概要）

1. **停止**：软件停止；解除使能；确认 `STOP_LATCHED`。
2. **隔离**：停止新系统运动服务；确认无硬件 publisher。
3. **恢复**：启动旧 8766 网关（或上一版本系统）。
4. **复核**：`GetBusServoState` 读取实际位置；与预期比较。
5. **记录**：证据包标记 `rollback`；写明原因、版本、位置。
6. **复盘**：未完成根因分析前不重跑同一场景。

禁止：

- 用编辑 `v1.0.0` 代码的方式“修复”回滚。
- 在未确认 publisher 集合的情况下同时启动两套运动服务。
- 用缓存位置代替总线实测。

## 7. 明确不做的事

- 不把 `jcheng-manipulation` 拆成多个仓库。
- 不重写 Git 历史、不 `filter-repo`、不移动标签。
- 不把厂商代码复制到公开仓库。
- 不在首批仓库中放站点密钥、真实 IP、令牌。
- 不让任何新模块在第一天拥有硬件发布权限。
- 不用“先把功能跑通，再补安全”的顺序。

## 8. 需要确认的决策

1. 是否接受 M0–M8 的阶段顺序与出口条件？
2. M5 是否允许在旧网关仍可只读运行时进行单关节实机测试？
3. M7 首个试点选 `jcheng-applications`（低风险）还是 `jcheng-teleop`（高价值）？
4. 是否接受“enforcement level C 未达成则 v1.0 标注 B”的发布策略？
5. 实机验收的监督人安排与档期如何确定？
