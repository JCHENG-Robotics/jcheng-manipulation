# ADR-0004：新仓库全新历史，基线只读

- 状态：提议
- 日期：2026-11-23

## 背景

`jcheng-manipulation v1.0.0` 是可复现实验基线：标签 `b3411e4`、
`release/manifest.json` 记录 8 个文件的 SHA-256、证据目录、测试计数与已知限制。
如果用 `git filter-repo` 把子目录拆成新仓库，会重写提交哈希，破坏标签、
校验和与外部引用。

## 决策

- `jcheng-manipulation` 保持原样：不迁代码、不改标签、不改清单、不改证据。
- 首批新仓库（`.github`、`jcheng-interfaces`、`jcheng-system`）使用**全新 Git 历史**。
- 新系统不在运行时依赖 `jcheng-manipulation` 的代码；只读引用其证据与语义。
- 需要复用的数值以“带来源哈希的 robot profile”复制，并由一致性检查证明等价。
- 仓库是否转移到组织、是否开启 v2，留待生态 v1.0 稳定后单独决策。

## 后果

正面：

- 基线证据链完整，标签与校验和不变。
- 新仓库历史干净，不携带研究脚本与归档学习包。
- 迁移可以并行进行，不需要停机。

负面：

- 新仓库没有旧提交历史，追溯需跨仓库引用。
- 需要维护“来源哈希/基线引用”文档。
- 短期存在两套代码/配置，必须明确哪套是权威。

## 替代方案

1. **`filter-repo` 拆分并保留历史。** 否决：改变提交哈希与发布证据。
2. **在新仓库用 submodule 引用基线。** 否决：嵌套仓库、凭据传播、版本漂移。
3. **直接在基线仓库开分支开发新系统。** 否决：违反冻结承诺，CI/证据耦合。

## 证据

- `VERSION` 1.0.0；`v1.0.0` -> `b3411e4`。
- `release/manifest.json` 的 checksums、components、known_limitations。
- `RELEASE.md` 的标签阶梯与回滚说明。
