# 系统架构：特权运动平面、控制权与安全

> 目标：让“所有实机运动都经过统一安全校验与控制权仲裁”成为**结构事实**，
> 而不是代码约定或操作纪律。

## 1. 总体拓扑

```text
┌──────────────────────────── 能力平面（域 42，非特权）────────────────────────────┐
│  jcheng-applications      jcheng-teleop      jcheng-learning      jcheng-mobile  │
│  （任务编排/UI）           （遥操作）          （训练/推理）          （底盘能力）    │
│         │ HTTP/WS               │ ROS 意图           │ ROS 意图            │ ROS 意图 │
│         ▼                       ▼                    ▼                     ▼        │
│  ┌──────────────────────────────────────────────────────────────────────────┐    │
│  │ jcheng_authority（租约）  jcheng_motion 前端  jcheng_gateway（HTTP/WS）   │    │
│  └──────────────────────────────────────────────────────────────────────────┘    │
└───────────────────────────────────────┬───────────────────────────────────────────┘
                                        │ 进程内/受控桥（不跨不可信网络）
┌───────────────────────────────────────┴──────────── 特权运动平面（域 41）──────────┐
│  jcheng_safety（校验/锁存/看门狗）   jcheng_motion 执行器（唯一命令发布者）          │
│  jcheng_guard（发布者白名单/域审计）  jcheng_telemetry（实测状态/证据）             │
└───────────────────────────────────────┬───────────────────────────────────────────┘
                                        │ 仅 jcheng_hardware 双上下文
┌───────────────────────────────────────┴──────────── 厂商域（域 0）─────────────────┐
│  ros_robot_controller · servo_controller · 相机 · TF · 底盘电机                   │
│  串口/总线/设备只由厂商节点持有                                                     │
└───────────────────────────────────────────────────────────────────────────────────┘

仿真域（域 43）：jcheng_testkit + Mock 厂商节点 + CI。与 0/41/42 完全隔离。
```

### 1.1 域规划

| 域 | 名称 | 成员 | 目的 |
|---|---|---|---|
| 0 | 厂商域 | 厂商 ROS 节点 | 保持厂商栈原样；只有硬件桥加入 |
| 41 | 特权运动域 | `jcheng_hardware`、`jcheng_safety`、`jcheng_motion` 执行器、`jcheng_guard`、`jcheng_telemetry` | 唯一能发布硬件命令的域 |
| 42 | 能力域 | `jcheng_motion` 前端、`jcheng_authority`、`jcheng_gateway`、规划、遥操作、学习、应用 | 模块只能提交意图、读状态 |
| 43 | 仿真域 | `jcheng_testkit`、Mock 厂商节点、E2E | CI 与离线验收 |

域隔离通过每个进程的 `ROS_DOMAIN_ID` 与 CycloneDDS 配置实现；禁止在能力域
进程中继承或覆盖为 0/41。M4 起加入 SROS2 权限（见第 8 节成熟度）。

### 1.2 为什么不把所有节点放在一个域

单域下任何进程都可以发布 `/ros_robot_controller/bus_servo/set_position`。
“代码里不写”无法防止误配置、旧脚本残留、第三方包或未来模块的越界。
分域让“看不到硬件话题”成为默认状态，而不是纪律要求。

## 2. 进程职责

| 进程 | 域 | 职责 | 明确不做 |
|---|---|---|---|
| `jcheng_hardware` | 0 + 41 | 厂商话题/服务适配；唯一硬件命令发布；总线实测读取；`RobotState` | 不做安全判断、不做租约、不接受外部命令 |
| `jcheng_safety` | 41 | 状态看门狗、限位/轨迹/工作空间校验、停止锁存、使能状态机 | 不执行运动、不发布硬件命令 |
| `jcheng_guard` | 0 + 41 | 监控硬件命令话题的发布者白名单、域/配置异常；违规锁存停止 | 不代替安全校验 |
| `jcheng_motion`（前端） | 42 | `ExecuteMotion` action、契约/租约/能力/幂等检查、排队与抢占 | 不直接发布硬件命令 |
| `jcheng_motion`（执行器） | 41 | 轨迹插值/S 曲线、已规划 `JointTrajectory` 的执行、底盘脉冲、夹爪时序、总线确认 | 不绕过安全校验、不接受未批准命令 |
| `jcheng_authority` | 42 | 租约申请/续租/释放/撤销、优先级、TTL、审计 | 不碰硬件 |
| `jcheng_gateway` | 42 + HTTP | 外部 API、认证、限流、OpenAPI、WS 推送 | 不发布 ROS 硬件命令 |
| `jcheng_telemetry` | 41 + 42 | 状态缓存、`measured|commanded` 标注、只读相机/TF 镜像、证据包 | 不参与控制决策 |
| `jcheng_bringup` | — | launch、启动顺序、域与参数、健康检查 | 不自动启动厂商容器 |
| `jcheng_testkit` | 43 | Mock 厂商、故障注入、回放、场景运行器 | 不连接实机 |

### 2.1 规划与执行分离

- MoveIt 在目标架构中是**只规划**：调用 `/move_action` 时 `planning_options.plan_only=true`，
  或使用 `/plan_kinematic_path`；返回 `RobotTrajectory`。
- 轨迹转换为 `jcheng_interfaces/JointTrajectory`，作为 `ExecuteMotion` 的载荷提交。
- **MoveIt 的控制器执行路径必须关闭或不被授予硬件发布权限。**
- 这样即使规划器被替换、被外部模块调用，也不能直接把轨迹送到舵机。

这是与 v1.0.0 的关键差异：当前 `armpi_grasp_planner` 可以通过
`/move_action` 触发执行；新系统不允许。

## 3. 控制权仲裁

### 3.1 租约模型

- 每个执行器作用域（`arm`、`gripper`、`base`）同一时刻只有一个**独占租约**。
- `scope=full` 一次性占用三个作用域，用于整机任务。
- 租约包含 `lease_id`、持有者、作用域、优先级、TTL、是否要求 deadman、契约版本。
- 租约默认 TTL：任务 30 s（可续至 300 s），遥操作 1 s（10 Hz 续租），诊断 10 s。
- 进程重启、配置变化、安全锁存、总线未知：所有租约立即失效。

### 3.2 优先级与抢占

| 优先级 | 主体 | 抢占规则 |
|---|---|---|
| 100 | 现场操作员 | 可抢占任何租约；撤销后 100 ms 内停止 |
| 60 | 应用任务 | 可抢占 40/20/10 |
| 40 | 遥操作 | 可抢占 20/10 |
| 20 | 学习/自动策略 | 不可抢占更高优先级 |
| 10 | 诊断/标定 | 仅在系统 `DISARMED` 且无其他租约时授予 |

抢占必须产生审计事件：被抢占方收到 `LEASE_PREEMPTED`，在飞运动返回
`ABORTED`，不得静默切换。

### 3.3 Deadman 与防重放

- `motion_source`（遥操作、学习推理）必须使用连续命令流：`seq` 严格递增，
  `stamp` 在 200 ms 窗口内；间隔超过 `deadman_ms`（默认 300 ms）立即停止。
  流契约见 `jcheng_interfaces/TeleopCommand.msg`；仲裁器采样后仍走同一安全校验。
- 一次性命令（step/pose/G-code 式任务）不要求连续流，但租约 TTL 必须覆盖执行。
- `idempotency_key` + 命令哈希缓存 24 h；相同 key 不同载荷返回
  `IDEMPOTENCY_CONFLICT`。
- 拒绝重放旧命令：`stamp` 超出窗口或 `seq` 回退。

### 3.4 单一权威

Studio 当前在后端内实现 `SafetySupervisor / LeaseManager / PreviewTokenManager`。
但这个权威只覆盖“经过后端的调用者”：

- 租约存在后端进程内，重启即丢失（`backend/app/safety/lease.py:36-40`）。
- 网关没有 lease/session 概念；持有共享 token 可直接
  `POST /motion/dispatch`（`ros2_gateway/server.py:225-251`）。
- 工作空间/桌面/FK 门禁只在后端（`backend/app/safety/pose_gate.py:106-238`），
  网关只做关节/step/速度检查（`motion.py:543-729`）。
- 机械臂与底盘没有交叉互锁；stop 只发机械臂 hold，不归零底盘
  （`node.py:294-316,739-802`）。
- `revoke()` 存在但没有路由暴露（`lease.py:113-115`）。

目标架构把控制权上移到 `jcheng_authority` + `jcheng_motion`：

- 应用层（含 Studio）只持有**客户端会话**，不持有安全权威。
- 预览 token 由 `ValidateMotion` 的 `validation_id` 取代，绑定命令哈希、单次使用。
- 网关只是 API 适配器，不保存运动权限；权限由租约 + 安全状态决定。
- 迁移期允许 Studio 后端作为“客户端适配器”，但不得再独立判定安全或租约；
  它必须调用系统服务，否则视为迁移未完成。**双权威是停止条件。**

## 4. 安全状态机

```text
                    ┌──────────────┐
      启动 ────────>│  DISARMED    │<──────────────┐
                    └──────┬───────┘               │
                           │ ArmSystem(检查清单)     │ ResetSafety(条件满足)
                           ▼                       │
                    ┌──────────────┐               │
                    │  ARMED_IDLE  │               │
                    └──────┬───────┘               │
                           │ 接受运动               │
                           ▼                       │
                    ┌──────────────┐   违规/停止    │
                    │ MOTION_ACTIVE│───────────────┤
                    └──────┬───────┘               │
                           │ 完成                   │
                           └──────> ARMED_IDLE      │
                                                   ▼
                    ┌──────────────────────────────────┐
                    │ STOP_LATCHED（含 UNKNOWN 子状态） │
                    └──────────────────────────────────┘
                                   │ 配置/总线/内部错误
                                   ▼
                    ┌──────────────┐
                    │    FAULT     │  只能重启进程/重新使能
                    └──────────────┘
```

规则：

- 启动后默认 `DISARMED`；不自动使能。
- 使能需要操作员身份、检查清单哈希、确认短语；检查清单包含“工作区清空、
  机械臂有支撑、无人员接触、已知无急停”等。
- `STOP_LATCHED` 只能通过 `ResetSafety` 清除；清除后回到 `DISARMED`，
  必须重新使能。
- `MOTION_OUTCOME_UNKNOWN` 是 `STOP_LATCHED` 的原因码之一；清除前必须完成
  一次成功的总线读数并确认位置在预期范围内。
- 配置哈希、profile 哈希、契约哈希任一不匹配：拒绝使能。
- 总线实测状态流超过 0.5 s 未更新：进入 `STOP_LATCHED`。

### 4.1 校验清单

`jcheng_safety` 对每个命令执行（顺序固定，失败即拒）：

1. 契约版本与哈希匹配。
2. 能力已登记，`source` 匹配，作用域匹配租约。
3. 租约有效、未过期、未被抢占；deadman 满足。
4. 安全状态为 `ARMED_IDLE` 或 `MOTION_ACTIVE`，且未锁存。
5. **总线实测状态**新鲜（≤ 0.5 s），关节齐全；命令缓存只能作为
   `truth=commanded` 的辅助信息，不能单独满足本项。
6. 起点与当前实测状态差 ≤ `max_start_state_rad`（当前 0.08）。
7. 关节位置在 profile 限位内。
8. 每点速度/加速度在 profile 上限内。
9. 轨迹时长/点数在 profile 上限内；时间严格递增。
10. TCP 工作空间在 `base_link` 包围盒内（FK 可用，失败关闭）。
11. TCP 距桌面平面 ≥ `clearance_m`（当前 10 mm）。
12. 底盘脉冲在 duty/时长上限内；绑定“标定失效”标记。
13. 夹爪目标在行程内；要求总线确认。
14. 命令速率/轨迹点数速率在限流内。
15. 无 `UNKNOWN` 锁存；无 guard 违规；无未授权发布者。
16. 幂等键未冲突；校验 ID（如有）未使用且未过期。

未来增加（需单独评审）：自碰撞模型、电流/力矩上限、关节温度、线缆约束。

### 4.2 停止语义

| 层级 | 行为 | 延迟目标 | 说明 |
|---|---|---|---|
| 安全锁存 | 状态置 `STOP_LATCHED`；执行器停止发送新设定点 | ≤ 50 ms | 软件 |
| 机械臂 | 保持最后位置（持续发送当前位置） | ≤ 100 ms | 依赖总线；不是抱闸 |
| 底盘 | 四通道占空比置 0 | ≤ 100 ms | 厂商 0.5 s 看门狗兜底 |
| 夹爪 | 保持当前位置 | ≤ 100 ms | 不主动松开 |
| 硬件急停 | 不存在 | — | 明确不声称 |

**必须在文档和 UI 中使用“软件停止/停止请求”，不得写“急停”。**

## 5. 运动执行管线

```text
能力模块
  │ 1. AcquireLease（域 42）
  ▼
jcheng_authority ──> ControlLease
  │
  │ 2. ExecuteMotion(goal)（域 42）
  ▼
jcheng_motion 前端
  ├─ 契约/能力/租约/幂等/限流
  ├─ 3. 由 jcheng_motion 的域 41 节点调用 ValidateMotion（安全节点）
  │     └─ 拒绝 -> REJECTED（无运动）
  ├─ 4. 排队（每作用域一个在飞命令）
  ▼
jcheng_motion 执行器（域 41）
  ├─ 5. 生成设定点 / 执行已规划的轨迹 / 底盘脉冲 / 夹爪时序
  ├─ 6. jcheng_hardware 发布厂商命令（域 0）
  ├─ 7. 总线 GetBusServoState 确认（域 0）
  └─ 8. 结果/证据（域 41 -> 42）
```

### 5.1 分 profile 执行

| profile | 来源 | 执行方式 | 完成判定 |
|---|---|---|---|
| `moveit` | MoveIt plan-only 轨迹 | 轨迹插值 + 总线流式设定点 | 总线读数在容差内 |
| `step` | 单关节小步 | 定时插值，最大步长 0.35 rad | 总线读数 ±8 脉冲 |
| `pose` | 目标位姿 | 系统 IK + FK 校验 + 工作空间/桌面检查 | 总线读数 + FK |
| `fast` | 密集 S 曲线 | 4.0 rad/s / 20 rad/s²，逐段校验 | 总线读数 + 稳定判据 |
| `base` | 四通道脉冲 | duty ≤ profile 上限、时长 ≤ 2 s、结束置零 | `open_loop`，明确标记 |
| `gripper` | 弧度目标 | 定时 + 总线读数 | 总线读数 + 堵转范围 |

**fast 不再绕过安全节点。** v1.0.0 的 `profiles.fast` 绕过是历史事实；
新系统把它重新实现为 `jcheng_motion` 内部的受控 profile：逐段调用安全校验、
要求 `verify_bus=true`、使用同一租约与停止路径。性能预算：单段校验 ≤ 10 ms，
整条 7 阶段轨迹校验 ≤ 50 ms；超出预算则回退到较低速度，而不是绕过校验。

### 5.2 MoveIt 适配

- 规划输入：`JointTrajectory` 或位姿目标。
- 规划输出：`moveit_msgs/RobotTrajectory` -> `JointTrajectory`。
- 执行：由 `jcheng_motion` 执行器流式发送，不调用 MoveIt 的 execute。
- 碰撞场景（桌面、D435i 碰撞盒）由规划侧维护；执行侧仍然做工作空间/桌面
  间隙的独立检查，不依赖规划器的结论。

## 6. 硬件桥

### 6.1 厂商接口映射

| 能力 | 厂商接口 | 方向 | 备注 |
|---|---|---|---|
| 关节/夹爪命令 | `/servo_controller`（`ServosPosition`） | 发布 | 唯一发布者：`jcheng_hardware`；厂商 `controller_manager` 负责 ID 过滤与插值 |
| 原始总线下发 | `/ros_robot_controller/bus_servo/set_position` | **禁止** | 绕过厂商控制器；guard 监控，出现即锁存 |
| 总线实测 | `/ros_robot_controller/bus_servo/get_state`（`GetBusServoState`） | 调用 | 负寄存器读取会崩溃，必须递增读取 |
| 关节命令缓存 | `/joint_states`、`/controller_manager/servo_states` | 订阅 | 仅作 `commanded`，不作完成判定 |
| 底盘 | `/ros_robot_controller/set_motor_speeds`（`MotorsSpeedControl`） | 发布 | 四通道，开环 |
| 电池 | `/ros_robot_controller/battery`（`UInt16`） | 订阅 | 只读 |
| 相机 | `/depth_cam/rgb/image_raw`、D435i UVC/深度 | 订阅 | 只读 |

### 6.2 命令合并与速率

- 关节与夹爪共享一条总线；`jcheng_hardware` 负责合并同一控制周期的设定点，
  避免同一舵机在一个周期内收到两个命令。
- 默认命令速率：轨迹 20–50 Hz；快速路径按段；夹爪 100 raw/s 等效弧度速率。
- 每个命令带递增序号；硬件桥拒绝回退序号。
- 总线读与写分离：读操作使用独立客户端，负寄存器保护；读失败返回
  `BUS_READ_FAILED`，执行器锁存 `UNKNOWN`。

### 6.3 启动与缓存重同步

- 厂商节点启动时的 `startup_check` 会移动机械臂。系统**不自动启动厂商容器**；
  启动属于受监督操作，必须满足物理前置条件并记录证据。
- 系统启动后、使能前，必须用 `GetBusServoState` 读取实际位置，并与缓存对齐；
  在完成前 `jcheng_safety` 保持 `DISARMED`。
- 缓存与实测不一致时，不允许“以缓存为准”继续；必须重新同步。

## 7. 网关、认证与审计

- 网关是唯一外部入口；应用层不直接连 ROS。
- 认证：阶段 1 使用每操作员令牌（非共享、可轮换）；阶段 2 支持 OIDC。
- 传输：默认仅 localhost；跨机访问必须 TLS 反向代理；禁止把令牌嵌入前端构建。
- 授权：`viewer`（只读）、`operator`（租约/运动/停止/使能）、`admin`（撤销/配置）。
- 限流：每会话命令速率、失败次数、并发租约；异常触发审计告警。
- 审计：所有租约、校验、执行、停止、复位、配置变化写入只追加存储（SQLite/JSONL），
  带 `evidence_id`；导出 CSV/JSON 保留 schema 版本。
- 网关崩溃不影响已在执行的停止路径；停止由安全节点/硬件桥独立处理。

## 8. “不能绕过”的六层 enforcement

| 层 | 机制 | 失败时 |
|---|---|---|
| 1. 契约 | 契约没有原始寄存器/任意占空比原语 | 客户端无法表达危险命令 |
| 2. 静态 | `capability.yaml` 白名单 + CI `check_no_bypass.py` 扫描禁止话题/设备/import | PR 拒绝 |
| 3. 进程/OS | 能力模块容器无串口设备、无 host 网络、只读根、独立用户 | 无法访问设备/厂商域 |
| 4. DDS | 能力域 42 与厂商域 0 隔离；仅硬件桥双上下文 | 默认看不到硬件话题 |
| 5. 运行时 | `jcheng_guard` 监控命令话题发布者 GID/数量；违规锁存停止 | 停止并记录 |
| 6. 仲裁 | 单一执行器 + 租约 + 安全否决 + 幂等 | 未授权命令无法执行 |

### 8.1 成熟度分级

| 级别 | 条件 | 适用阶段 |
|---|---|---|
| A | 契约 + 静态检查 + 单一执行器（Mock） | M3 |
| B | A + 域隔离 + 容器权限 + guard | M4–M5 |
| C | B + SROS2 签名权限 + 只读根 + 独立用户 + 审计告警 | v1.0 目标 |

**诚实说明：** 在 SROS2 部署前，域隔离依赖进程环境不可被篡改；同主机同用户的
恶意进程仍可能覆盖 `ROS_DOMAIN_ID`。因此 M4–M5 的实机验收必须是受监督的，
且 v1.0 发布前应完成 SROS2 或等价的进程隔离。若未完成，发布说明必须标注
“enforcement level B”。

### 8.2 针对 v1.0.0 缺口的逐项关闭

审计发现的 G1–G16（见 `01-baseline-audit.md` 6.2）必须在系统设计中被逐项关闭，
不能以“新模块遵守约定”代替：

| 缺口 | 目标机制 | 验收 |
|---|---|---|
| G1 DDS 无认证 | 域 0/41/42 隔离；SROS2 权限；容器无设备 | S9、S10、图形审计 |
| G2 安全节点缺失时 fail-open | 仲裁器/网关必须收到新鲜 `SafetyState`；缺失即 `STOP_LATCHED`；禁止默认 false | S6、S7 |
| G3 限位来自可替换 JSON | robot profile 单一来源；profile 哈希握手；配置只读挂载 | S16 |
| G4 后端看不到 stop | `SafetyState` 在域 41/42 同步；网关/应用只读同一状态 | S6 |
| G5 停止不中止在飞 | 执行器每段检查停止；停止取消 action/profile；底盘立即置零 | S6、S14 |
| G6 校验可被调用方放宽 | 不允许调用方覆盖起点/速率；显式速率与位置差分交叉校验 | S8 |
| G7 缺关节回退/无 mapping 版本 | 全关节必填；无回退；`profile_hash` 进入握手 | S16 |
| G8 EEPROM/力矩可改 | 运行时不暴露 `SetBusServoState` 与原始 `set_position`；guard 监控；维护写操作独立审批 | S9 |
| G9 MoveIt action 直暴露 | MoveIt 只规划；不启动控制器；执行只走仲裁器 | S17 |
| G10 Fast CLI 无硬上限 | 快路径在仲裁器内，硬上限 + 逐段校验 | S8、S13 |
| G11 `/grasp`/手柄直发 | 生产启动不加载这些节点；guard 检测其发布 | S9 |
| G12 缓存冒充实测 | 总线实测为主；缓存标 `commanded`；看门狗读总线 | S7、S12 |
| G13 dispatch 超时不锁存 | 任何超时/网络失败 -> `UNKNOWN` 锁存；总线复核后才允许重试 | S12 |
| G14 stop 权限不对称 | stop 需操作员认证但不需要租约（任何已认证操作员都能停）；明确“软件停止” | S6、S15 |
| G15 厂商启动运动 | 不自动重启厂商容器；启动前置条件 + 物理监督 + 证据 | 运行手册 |
| G16 TCP-only 检查 | 保留 TCP/桌面守卫为最低线；自碰撞模型列为后续独立项目 | 文档明示 |

其中 G2、G5、G12、G13 是**安全关键**：它们决定“停止是否真的停止”和
“完成是否真的完成”。任何一项未关闭，不得进入 M5 实机阶段。

## 9. 故障与降级矩阵

| 故障 | 检测 | 动作 | 恢复 |
|---|---|---|---|
| 总线实测状态过期（`/joint_states` 仅辅助） | 安全看门狗 0.5 s | `STOP_LATCHED`；在飞命令 `ABORTED` | 状态恢复 + 复位 + 重新使能 |
| 安全违规 | 校验返回 violations | 拒绝；在飞则中止 | 修正命令/配置 |
| 总线读失败 | 服务超时/错误 | `UNKNOWN` 锁存；停止 | 总线复核 + 人工复位 |
| 租约过期 | authority TTL | 中止；停止 | 重新申请 |
| 租约被抢占 | authority 事件 | 中止；返回 `LEASE_PREEMPTED` | 等待/重新申请 |
| 网关断开 | WS/HTTP 心跳 | 租约 TTL 到期后停止；UI 只读 | 重连/重新申请 |
| 硬件桥崩溃 | 心跳/状态停更 | 安全锁存；底盘看门狗置零；机械臂保持最后命令 | 重启桥 + 总线复核 |
| 厂商节点崩溃 | 话题停更 | 锁存；**不重启整个容器**（会触发 startup_check 运动） | 仅重启节点 + 重同步 |
| guard 违规 | 发布者白名单不匹配 | 立即锁存；拒绝新命令 | 排查发布者 + 复位 |
| 配置/契约哈希不匹配 | 启动/握手 | 拒绝使能 | 部署正确版本 |
| 时钟偏移超限 | 时钟监控 | 拒绝使能/锁存 | 同步时钟 |
| 电源不足/电池低 | 电池话题 | 拒绝新任务；提示 | 充电/换电 |

## 10. 部署拓扑

### 10.1 机器人端（Pi 5）

```text
厂商容器（既有，不改）
  ros_robot_controller · servo_controller · 相机 · TF
        │ 域 0
┌───────┴──────────────────────────────────────────────┐
│ jcheng 特权容器（无串口设备，仅 DDS）                  │
│  jcheng_hardware（域 0/41）· jcheng_safety（41）       │
│  jcheng_motion 执行器（41）· jcheng_guard（0/41）      │
│  jcheng_telemetry（41/42）· jcheng_gateway（42/HTTP）  │
└───────┬──────────────────────────────────────────────┘
        │ 域 42，有线 10.42.0.x
┌───────┴──────────────────────────────────────────────┐
│ 工作站：规划（MoveIt Humble 容器）· 能力模块 · 应用     │
└──────────────────────────────────────────────────────┘
```

- 特权容器不挂载 `/dev/tty*`、不挂载 Docker socket、不使用 `privileged`。
- **网络边界：** Pi 的 nftables 只允许工作站访问域 42 的系统端口；厂商 DDS 端口
  （7400–7500/udp 与发现端口）只允许本机特权容器/回环。工作站的进程即使把
  `ROS_DOMAIN_ID` 改成 0，也无法到达厂商域。能力容器使用独立 Docker network，
  没有到厂商容器的路由。这是 enforcement level B 的预防层，SROS2 是进一步加固。
- **JCHENG 全栈统一 CycloneDDS**，使用单播 peer 列表；域 41 不对工作站开放。
  基线网关默认 Fast DDS，且厂商服务在 Fast DDS 下不可互通；迁移期不允许
  “一半节点 Fast DDS、一半 CycloneDDS”再跨 RMW 调服务。跨 RMW 只允许走话题，
  且必须在域边界由硬件桥转换。
- 系统服务：`jcheng-hardware`、`jcheng-safety`、`jcheng-motion`、
  `jcheng-authority`、`jcheng-gateway`、`jcheng-guard`；启动顺序固定，
  启动脚本轮询厂商话题就绪（只检查，不重启容器）。
- 8765/8766 遗留网关在迁移期保留为只读/兼容入口；新系统使用独立端口，
  默认仅 localhost。

### 10.2 工作站端

- 能力模块容器：无设备、无 Docker socket、只加入域 42。
- MoveIt 规划容器：只规划，不执行；不加入域 41。
- 应用/前端：只访问网关 HTTP/WS。

### 10.3 时钟与网络

- 保留现有笔记本每 60 s 推送时钟的机制；控制决策用本机单调时钟。
- 安全节点拒绝使能的条件包括：跨主机时钟偏移超过配置阈值（建议 5 s；
  当前基线约 2 s 领先，需实测确认）。
- 网络分区：能力域断连时，租约到期停止；不允许“最后命令一直执行”。

## 11. 观测与指标

必须采集并可导出：

- 校验延迟（P50/P95/P99）、执行延迟、总线读延迟。
- 停止锁存延迟、停止传播延迟。
- 租约争用/抢占/过期次数。
- guard 违规、未知发布者、域异常。
- `UNKNOWN` 结果数量与恢复时间。
- 每条命令的 profile、点数、时长、结果、证据 ID。
- 硬件桥队列深度、命令合并次数、总线错误。

验收指标在 `06-ci-cd-acceptance.md` 中定义；运行指标写入证据包。

## 12. 明确不声称的能力

- 不是功能安全系统；没有 SIL/PL 认证。
- 没有硬件急停、抱闸、独立编码器、力矩传感、自碰撞模型。
- 软件停止不能替代断电/物理隔离。
- 底盘开环、无里程计；任何底盘运动使桌面标定失效。
- 厂商启动检查、厂商服务直连、固件行为不在软件否决范围内；只能通过
  启动前置条件、域隔离、物理监督和证据管理。
- MoveIt 规划器不是安全认证的碰撞检查器。
